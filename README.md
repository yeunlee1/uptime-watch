# uptime-watch

정해 둔 주소 몇 곳이 살아 있는지 5분마다 확인합니다. 하나라도 이상하면 실행이 실패로 끝나고, 깃허브가 저장소 주인에게 메일을 보냅니다.

## 감시 대상

주소는 저장소에 두지 않고 시크릿 `WATCH_TARGETS` 에 넣습니다. 각 줄이 대상 하나입니다.

```
이름|주소|응답에 있어야 할 낱말
```

세 번째 칸이 핵심입니다. 응답 코드만 보면 **응답은 오는데 내용이 깨진 경우**를 놓칩니다. 있어야 할 낱말까지 확인해야 그것도 잡힙니다.

세 번째 칸을 비우면 응답 코드만 봅니다.

## 헛알람을 줄이는 장치

- 한 번 실패했다고 바로 알리지 않고 5초 간격으로 **세 번**까지 다시 눌러 봅니다
- 15초 안에 응답이 없으면 실패로 봅니다
- 세 번 다 실패해야 메일이 갑니다

헛알람이 잦으면 진짜 장애가 왔을 때도 무시하게 됩니다. 그래서 일부러 느슨하게 잡았습니다.

## 대상을 고치려면

**Settings → Secrets and variables → Actions → `WATCH_TARGETS`** 를 고칩니다. 파일은 건드리지 않아도 됩니다.

## `상태.md` 는 왜 있나

깃허브는 **60일 동안 커밋이 없으면 예약 실행을 꺼 버립니다.** 그대로 두면 두 달 뒤 감시가 조용히 멈춥니다. 그것을 막으려고 정상인 날 하루 한 줄씩 기록을 남깁니다. 파일 내용 자체는 중요하지 않습니다.

## 손으로 돌려보려면

Actions 탭 → `주소 감시` → `Run workflow`
